## Slide 10 — Technology Stack

Now let me explain our technology choices.

We have **three layers** — frontend, backend, and infrastructure.

**Frontend** — We use Next.js 16 with TypeScript. Tailwind CSS for styling. Redux Toolkit for state. Better Auth for authentication.

We chose Next.js because it gives us fast server-side rendering and full TypeScript support.

**Backend API** — Node.js 22 with Express.js and TypeScript. Prisma ORM for database access. JWT plus bcrypt for secure authentication. Zod for input validation.

We chose Express.js because it works perfectly with Prisma for type-safe database queries.

**Infrastructure** — PostgreSQL with pgvector for AI semantic search. AWS S3 for file storage. Redis for caching. Stripe for billing. Gemini and OpenAI for AI. Vercel for deployment.

All of this is one full-stack TypeScript monorepo — frontend and backend share type safety end to end.

> *(~130 words — approx 1 min 40 sec)*

## Slide 11 — System Architecture

Let me now explain how the system is designed.

ScholarFlow uses a **three-tier decoupled architecture**.

**Tier one — User Layer.**
Any user — researcher, student, or team admin — accesses ScholarFlow from a browser on desktop or mobile.

**Tier two — Frontend Layer.**
The Next.js 16 app runs on Vercel. It handles the user interface, authentication, state management, and the text editor.

**Tier three — Backend API Layer.**
An Express.js REST API runs on Railway. It handles all business logic — auth, papers, collections, AI, and billing.

The backend connects to three service groups:

First — **PostgreSQL** with pgvector for semantic search. Redis for caching. Prisma for type-safe queries.

Second — **AWS S3** for all file storage. Stripe for billing.

Third — **AI APIs** — Gemini 3.5 Flash and OpenAI GPT-5.5 — with automatic fallback.

Frontend and backend are completely separate — REST API only. No shared code between layers.

## 🗒️ Quick Tips for Non-Native Speakers

- **Speak slowly.** Slow is clear. Clear is confident.
- **Pause after each sentence.** Give the audience time to understand.
- **Don't memorize word-for-word.** Understand the main idea. Speak naturally from that.
- **Use the slide as a guide.** Look at the slide, then say what it shows.
- **Practice 3 times before the day.** You will feel much more relaxed.
- **If you forget a word — describe it simply.** "AI reads the paper automatically" is better than a complex sentence said incorrectly.
- **Make eye contact with the audience** — not just the screen.
