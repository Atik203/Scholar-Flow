\section{System Testing and Validation}
System testing and validation were rigorously conducted to ensure the reliability, security, performance, and correctness of the ScholarFlow platform. Both automated test suites and end-to-end integration workflows were exercised across all primary modules and user roles.

The following testing activities were executed:
\begin{itemize}
\item \textbf{Automated Test Suite Execution}: A comprehensive suite of 21 test suites comprising 59 automated unit, integration, and Supertest API tests was executed across the backend services and frontend state reducers, maintaining a 100\% pass rate (\texttt{yarn test} green).
\item \textbf{Authentication and Role-Based Access Control}: Registration, credential sign-in, session recovery, and JWT token rotation were verified. Route guards and API middleware were tested against privilege escalation, guaranteeing that unauthorized role operations return HTTP 403 Forbidden.
\item \textbf{Paper Upload and S3 Presigned URL Validation}: File size limits, MIME type enforcement, and presigned S3 upload handshakes were validated under concurrent uploads, confirming that AI metadata extraction failures gracefully fall back without blocking paper ingestion.
\item \textbf{Real-Time Synchronization and Collaboration}: Socket.IO connections and Y.js state synchronization were evaluated across simulated multi-client browser sessions, verifying collaborative text editing, typing indicators, and reliable offline reconnection.
\item \textbf{Stripe Billing and Webhook Idempotency}: Local Stripe CLI webhook forwarding was utilized to test \texttt{checkout.session.completed} and subscription renewal events, validating idempotency guards against duplicate webhooks and confirming the 7-day grace-period sweeper.
\item \textbf{AI Pipeline and Access Boundary Verification}: Contextual Q\&A, summarization, and semantic search endpoints were tested to guarantee that queries never access papers outside the authenticated user's workspace boundaries, with all generated content sanitized to prevent cross-site scripting (XSS).
\item \textbf{Performance and Latency Budgets}: Backend query tracing verified the $<$50\,ms database execution budget, while pgvector HNSW indexing maintained vector similarity search times consistently below 300\,ms under loaded catalog queries.
\end{itemize}

These testing activities confirmed the structural integrity, data consistency, and operational resilience of the platform across both individual and multi-tenant workflows.
